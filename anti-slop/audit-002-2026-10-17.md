## Ringkasan Eksekutif

Audit menyeluruh ini mengevaluasi perkembangan sistem aplikasi **e-njajan** setelah penyelesaian Langkah 1 (Integrasi Supabase Backend & Realtime Database), penyederhanaan peran menjadi 2 aktor (*User / Pelanggan* dan *Petugas Kantin*), serta penerapan fokus metode **Pembayaran Tunai (Cash)** di kasir kantin.

Aplikasi telah memiliki arsitektur yang solid:
- Kompilasi produksi Next.js 16 (Turbopack) sukses dalam waktu 782ms.
- ESLint dan TypeScript lulus dengan **0 error dan 0 warning**.
- Bebas dari karakter terlarang (*em dash* / `—`) di seluruh berkas kode.
- Sinkronisasi WebSocket Supabase Realtime aktif untuk penyebaran pembaruan pesanan dan pengaturan kantin.
- Seluruh dialog modal telah mendukung aksesibilitas keyboard (tombol `Escape`, atribut dialog WCAG, dan dismiss backdrop).

Berdasarkan audit mendalam terhadap seluruh alur operasional, ditemukan **6 temuan teridentifikasi** (nomor 8 s/d 13, melanjutkan nomor dari `audit-001`). Sesuai aturan **antislop Mode 2**, temuan dikelompokkan dengan prioritas berjenjang (Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW).

## Daftar Temuan Bernomor (Numbered Findings)

### 8. R-26 / C-2 Sinkronisasi Stok Supabase saat Pembuatan & Pembatalan Pesanan - HIGH
- **Lokasi**: [`src/context/AppContext.tsx`](file:///Users/fadhel/Documents/e-njajan/src/context/AppContext.tsx) (`createOrder` baris 568-577 & `cancelOrder` baris 672-680)
- **Kategori**: Hard Gate / Fungsional & Integritas Data
- **Deskripsi Masalah**: Saat pelanggan membuat pesanan baru (`createOrder`), stok menu dikurangi secara lokal di state React dan `localStorage`, namun belum ada pemanggilan update stok ke tabel `menu` di Supabase (`supabase.from("menu").update({ stock: newStock }).eq("id", item.id)`). Hal yang sama terjadi saat pesanan dibatalkan (`cancelOrder`), pemulihan stok hanya terjadi secara lokal. Akibatnya, browser petugas kantin di perangkat lain tidak menerima pembaruan sisa stok secara real-time via WebSocket.
- **Rekomendasi Perbaikan**: Tambahkan sinkronisasi batch/iterasi update sisa stok ke tabel `menu` Supabase saat `createOrder` dan saat `cancelOrder`, sehingga seluruh perangkat terhubung selalu melihat kuantitas stok yang sinkron.

### 9. R-26 / C-2 Sinkronisasi Pembatalan Pesanan ke Database Supabase - HIGH
- **Lokasi**: [`src/context/AppContext.tsx`](file:///Users/fadhel/Documents/e-njajan/src/context/AppContext.tsx) (`cancelOrder` baris 658-705)
- **Kategori**: Hard Gate / Fungsional & Siklus Pesanan
- **Deskripsi Masalah**: Ketika pelanggan membatalkan pesanan yang berstatus menunggu konfirmasi, fungsi `cancelOrder` hanya mengubah state lokal pesanan menjadi `"dibatalkan"`. Tidak ada pemanggilan `supabase.from("orders").update({ order_status: "dibatalkan" }).eq("id", orderId)`. Dampaknya, di database Supabase dan di layar petugas kantin, pesanan tersebut tetap tercatat aktif (*menunggu_konfirmasi*).
- **Rekomendasi Perbaikan**: Tambahkan pemanggilan update status ke tabel `orders` di Supabase pada fungsi `cancelOrder` agar pembatalan langsung terpropagasi ke dasbor petugas secara real-time.

### 10. C-4 / R-35 Optimasi Indeks & Integritas Constraint Database Supabase - MEDIUM
- **Lokasi**: [`supabase/schema.sql`](file:///Users/fadhel/Documents/e-njajan/supabase/schema.sql)
- **Kategori**: Purpose-Gate / Ketahanan & Performa Database
- **Deskripsi Masalah**: Skema tabel `orders` saat ini belum memiliki indeks sekunder pada kolom-kolom yang sering difilter atau diurutkan (`customer_name`, `order_status`, `created_at`). Selain itu, belum ada check constraint SQL eksplisit pada nilai `order_status` dan `payment_method`.
- **Rekomendasi Perbaikan**: Tambahkan `create index if not exists idx_orders_customer on public.orders(customer_name);`, `create index if not exists idx_orders_status on public.orders(order_status);`, serta constraint nilai status valid pada `schema.sql` untuk memastikan integritas dan kecepatan query jangka panjang.

### 11. R-26 / C-2 Sinkronisasi Aksi Reset Data Demo dengan Cloud Database - MEDIUM
- **Lokasi**: [`src/components/staff/StaffDashboard.tsx`](file:///Users/fadhel/Documents/e-njajan/src/components/staff/StaffDashboard.tsx) & [`src/context/AppContext.tsx`](file:///Users/fadhel/Documents/e-njajan/src/context/AppContext.tsx) (`resetDemoData` baris 767)
- **Kategori**: Purpose-Gate / Fungsional
- **Deskripsi Masalah**: Tombol "Reset Data Demo" di dasbor pengaturan staf saat ini hanya mereset data di state lokal browser. Jika aplikasi di-refresh atau dibuka di browser lain, pesanan riil yang tersimpan di Supabase akan terambil kembali sehingga petugas mengira data demo belum tereset.
- **Rekomendasi Perbaikan**: Berikan opsi konfirmasi pada modal reset untuk mereset data pesanan di Supabase (menghapus pesanan transaksi demo atau mengembalikan menu awal ke stok standar) sehingga pengujian demo konsisten di seluruh perangkat.

### 12. C-1 / C-3 Fitur Bantu Hitung Uang Tunai & Kembalian Cepat Kasir - LOW
- **Lokasi**: [`src/components/staff/StaffDashboard.tsx`](file:///Users/fadhel/Documents/e-njajan/src/components/staff/StaffDashboard.tsx)
- **Kategori**: Quality Locks / Pengalaman Operasional Kasir
- **Deskripsi Masalah**: Saat melayani pembayaran tunai di kounter, petugas langsung menekan tombol "Tandai Lunas Tunai". Pada jam istirahat sekolah yang padat dengan antrean siswa, kasir sering membutuhkan alat bantu hitung cepat kembalian (misalnya tombol pecahan uang diterima: Uang Pas, Rp 10.000, Rp 20.000, Rp 50.000, dan perhitungan kembalian instan).
- **Rekomendasi Perbaikan**: Tambahkan dialog/drawer kalkulator kembalian cepat opsional saat petugas mengonfirmasi pembayaran tunai, sehingga kasir dapat memverifikasi uang diterima dan kembalian siswa secara akurat sebelum pesanan ditandai lunas.

### 13. R-26 / C-4 Validasi & Peringatan Ruangan pada Profil Pengguna - LOW
- **Lokasi**: [`src/components/customer/ProfileView.tsx`](file:///Users/fadhel/Documents/e-njajan/src/components/customer/ProfileView.tsx)
- **Kategori**: Quality Locks / Ketahanan Form
- **Deskripsi Masalah**: Form profil pengguna memperbolehkan kolom kelas/ruangan dikosongkan. Meskipun `CheckoutModal` telah memvalidasi lokasi saat memilih pesan antar, pengguna yang baru menyetel profil tidak mendapatkan indikasi bahwa kelas/ruangan sangat disarankan untuk pengantaran makanan.
- **Rekomendasi Perbaikan**: Tambahkan petunjuk visual atau badge rekomendasi ("Direkomendasikan untuk pesan antar") pada input kelas/ruangan di halaman profil agar pelanggan memahami manfaat mengisi lokasi tersebut sejak awal.
